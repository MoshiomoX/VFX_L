# 引擎与渲染：交换链・计时・碰撞・光照・卡通・SSAO・影子

> 2026-11-13 从 CLAUDE.md 原样搬出（文字未改）。之后这一块的新记录直接追加到这里。

- **交换链 / 帧率**：`Graphics` 用 flip 型（`FLIP_DISCARD` 3 枚，backbuffer 无 MSAA；场景的 HDR RT 仍是 4x MSAA，BeginUI 里 resolve）。支持时带 `ALLOW_TEARING`，关垂直同步时 Present 用它（可变刷新的屏不撕裂）。`PresentSettings`（vsync / fpsCap）在 Debug Info 窗口「VSync」「FPS Cap」调，默认开垂直同步、不限帧；限帧在 `EndFrame` 里 Present 前等（高精度 waitable timer + 最后 2ms 自旋，Release 限 160 实测 160.0 fps、sd 0.1 ms）。Alt+Enter 的独占全屏已关（全屏用 F11 无边框窗口）。实测（2026-09-27）：旧的 blt 交换链开垂直同步时 Debug 也不会锁到 82.5 fps，所以换 flip 型对平均 fps 没影响，意义在于撕裂模式 / 可变刷新 / 限帧。
- **分段计时**：`Debug/FrameProfiler`（`PROFILE_SCOPE("名字")` 只测 CPU，`PROFILE_SCOPE_GPU("名字")` 再加 D3D11 timestamp 测 GPU，4 帧后读结果；1 秒平均的每帧 ms；`Application::Run` 开头 `BeginFrame`、末尾 `EndFrame`）。打点在主循环（输入、Update、Render、resolve+bloom+ImGui、Present）和战斗场景（gameplay 各段、各绘制阶段；绘制和 compute 的段都测 GPU）。战斗场景面板「Frame Profiler」，perf / stress 自测每段后多写一行（`名字 cpu/gpu`，`>` 表示层级）。GPU 值是两个时间戳的差：CPU 慢、GPU 在等命令时（Debug）会偏大，GPU 忙时（Release）才准。Present 长 = CPU 在等 GPU。

- **碰撞（CPU，`Collider/CollisionSystem`）**：碰撞体分「固定」（有 Rigidbody 且 `isStatic`：地形、装饰物碰撞盒、报酬箱、精英靶子）和「可动」（其余：玩家、CPU 投射物等）。固定的登记进稠密格子（CSR，4m 一格）并缓存，只有固定集合变化或有一个移动超过 0.5m 才重建；覆盖超过 64 格的（地面盒子、外墙、大高台）不进格子，单独列表。只做「可动 × 固定」和「可动 × 可动」配对，固定 × 固定不判定（本来就没人用，而且 AABB / 凸体之间不支持）。物理的推出用 `GatherStaticNear` 只查附近。`WorldCollider` 多了 `hasRigidbody` / `fixed`。**2026-10-04 加 `ColliderShape::HeightField`**（起伏地面，见「战斗地形 → 起伏」）：`ColliderComponent::heightField` / `WorldCollider::heightField`（`shared_ptr<const CollisionMath::HeightFieldShape>`），`BoundsOf` 按 halfExtents 算范围（否则会按半径算、宽相位漏掉），`Raycast` 用 `RaycastHeightField`，`OverlapSphere` / `TestPairShape` 不看它，物理里单独处理（竖直推出 + 下坡吸附）。**10-03 起固定的 `WorldCollider` 也缓存**：`m_WorldColliders` 前面是固定（实体 ID 和顺序不变就不重建；位置变了只重建那一个，超过 0.5m 才重建格子），后面是每帧重建的可动；以前每帧把所有碰撞体（凸体带 12 个平面）重拷一遍，给外围岩石加 131 个凸体时 Debug 多了 0.55 ms，缓存 + 岩石放 `Layer_Prop`（镜头射线 `Raycast` 是线性遍历，先按层过滤）+ 只给伸进 0.35m 以上的岩石加碰撞后，差距降到约 0.1 ms（`perf` 自测，`VFXL_NO_EDGE_COLLIDERS` 对比）。
- **光照**：`Shader/Common/Lighting.hlsli`（半球环境光 + 平行光和点光源的 GGX 高光）。点光源表是 `PointLightManager`（每帧一张，t6/t7）。
  - **分簇前向 Forward+（2026-10-23，用户问「现在是前向还是延迟」→ 我推荐不换延迟、升级成 Forward+ → 「开始吧，先量现状」）**：以前每个像素循环整张点光源表（上限 64，照不到的灯也要走一遍距离判断）。现在 `Graphics/Light/LightClusters`（`PointLightManager` 持有，`Clusters()`）把视锥切成 16×9 屏幕块 × 24 层（深度按指数切，`zNear` 1m〜`zFar` 250m，第 0 层从相机起、最后一层到无穷远），每帧在 `SceneBase::Render`（`Upload` 之后，GPU 弹 / 范围的灯已经追加完）用场景的 `m_Camera` 跑一次 `Shader/Light/LightClusterCS.hlsl`（一个簇一个线程，组内先把灯转到视空间放 groupshared，再拿球和簇的视空间 AABB 判交，每簇写 `MAX_POINT_LIGHTS / 32` 个 uint 位掩码；不用原子操作、不用索引表）。`Lighting.hlsli` 的 `PointLightShade` 用 `Shader/Common/LightClusters.hlsli` 的 `LightClusterOf`（世界坐标 × viewProj → 屏幕块 + `log(clip.w)` 的层）找到像素的簇，只循环掩码里的灯（`firstbitlow`）；簇的参数（viewProj / view / 投影倍率 / 分层）和掩码放在 PS 的 **t10（掩码）/ t11（`LightClusterInfo` 160B，C++ 同布局 `static_assert`）**，由 `PointLightManager::BindPS / UnbindPS` 一起绑；这一帧没建（没有相机的场景、或关掉）就绑 null → info 读出 0 → PS 退回全循环。所有受光 PS（模型 / PBR / 地形 / 草 / 落叶 / 经验球 / 液面）都走 `PointLightShade`，不用逐个改。**上限 64 → 256**（`MAX_POINT_LIGHTS` / `kMaxLights`，要保持 32 的倍数）。`PointLightAccum` 和 `PointLightShade` 不能中途 return（fxc 会在所有调用处报 X4000）；距离判断要先用距离平方、在半径内才算方向（第一版先算了 normalize 再判断，全循环比旧版慢了约 0.5 ms）。Lighting 面板「Point Light List (clustered)」：开关、热力图（每个像素访问了几盏：蓝 1 / 绿 4 / 红 16+，加在 specular 上）、分层范围。`VFXL_NO_CLUSTER=1` 退回全循环、`VFXL_CLUSTER_HEAT=1` 热力图（TEMP-TEST）。**实测**（Release 1600×900、关垂直同步、草原 seed 12345、没有敌人，自测 `VFXL_BATTLE_AUTOTEST=lightperf`，`Debug/AutoTest/AutoTestLightPerf.cpp`：玩家前方按 8×8 / 16×16 网格摆 CPU 点光源，每段 9 秒、记后 6 秒的平均帧时间和 FrameProfiler，最后两段开热力图截图；场上本来有 7 盏箱子 / 磁铁 / 门的灯）：0 盏 2.80 ms；画面内 64 盏 r6 全循环 3.67 → 分簇 3.17；**画面外 64 盏 3.44 → 2.80**（照不到的灯不再花钱）；64 盏 r12（重叠很多）4.26 → 4.04（帮不上多少，正常）；128 盏 r4 4.43 → 3.25；256 盏 r3 5.78 → 3.37；画面外 256 盏 5.52 → 2.88。改之前的旧版（上限 64）：画面内 64 盏 3.59、画面外 64 盏 3.39。截图亮度（画面中部平均）分簇 / 全循环 / 旧版一致到 1〜2 以内。**没验证**：D3D 调试层下有没有 HAZARD 警告、F2 / F4 / F6 编辑器里点光源的画面（逻辑上走同一条路）、Debug 的帧时间；敌人多的实战场景没量。测量脚本 scratchpad `RunPerf.ps1`（只在游戏窗口在前台时截图）。
- **卡通渲染（2026-10-04，用户：「尝试做一下卡通渲染」；三项都选推荐：两阶柔边 + 冷色暗部、全屏描边、全部物体）**：
  - **色阶**：`Lighting.hlsli` 的 `ShadeToon`，`ShadeLambert(…, worldPos)` / `ShadePBR(…, worldPos)` 在 `toonParams.x = 1` 时改走它，所以地形（TerrainPS）、模型 / 骨骼模型 / 树石（PS / PBR_PS）、GPU 雑魚、草（GrassPS）一起变；经验球、液面、粒子有自己的着色，不受影响。亮暗按 `N・L × 太阳影子` 做两阶（`ToonBand`：边界 `toonParams.y` 0.15，柔边 `z` 0.05，影子的边一起变硬）；亮面 = 满太阳 × `toonShadowTint.w` 0.85（N・L 不再压暗侧面，所以整体降一点）；暗面 = 半球环境光 × `toonShadowTint.rgb`（0.70, 0.78, 1.10，偏冷的蓝紫）；硬高光 = N・H 在 0.994〜0.997 的窄窗口 × `toonParams.w` 0.3（PBR 按粗糙度缩）；边缘光 `ToonRim`（N・V 的细带 × 只在侧向面 × 只在离镜头 18〜32m 内，`toonRim` 暖白 0.3）。硬高光也只在 18〜32m 内：远处低多边形岩石的圆角倒边会整条发亮，像塑料（自测看到的）。点光源保持平滑。参数加在 `LightBuffer` 影子块之后（C++ `LightTypes.h` 和 HLSL 同步，`static_assert`：toon 块在 368，`hasAlbedo` 移到 416），`Renderer::SetToon`；`SceneLighting` 持有（默认开，`Apply` 每帧写，`ClearFog` 关掉 → 其他场景仍是原来的光照），Lighting 面板末尾「Toon Shading」可调 / 开关。`VFXL_NO_TOON=1` 关（对比用）。
  - **描边**：`Graphics/PostProcess/Outline` + `Shader/PostProcess/OutlinePS.hlsl`（全屏三角形借用 `Sky/SkyVS`）。场景深度缓冲改成 `R24G8_TYPELESS` + DSV（D24S8）+ SRV（`R24_UNORM_X8`，MSAA 时 Texture2DMS，`Graphics::GetDepthSRV / GetSceneRTV / GetSampleCount`）。画法：解绑 DSV、读深度第 0 个样本，按投影矩阵还原成到眼睛的距离（`eye = _43 / (d − _33·_34)`）；对 4 个方向的相邻两点在 1/z 里插值预测中心深度（平面在屏幕上 1/z 是线性的，所以斜着看地面也不出线），中心比预测近出阈值 `threshold` 3.5%（相对自身深度）就算边 → 只描在靠前物体那一侧。用乘法混合（`DEST × src`）把下面的颜色压向 `tint`（0.06, 0.05, 0.10），所以不是死黑。线宽 `thickness` 2px（按 1080p 换算，第一版 1px 在 1600×900 几乎看不见），35〜90m 淡出。**绘制顺序**（战斗场景 `Render`）：模型 → 树石 → `Swarm::RenderOpaque`（雑魚 / 碎片 / 经验球）→ **描边** → 草 → `Swarm::RenderOverlay`（液面 / 圆影 / 警告圈 / 血条）→ 透明物 → 粒子 → UI。草在描边之后画（不然每根草叶都有线），雑魚的绘制为此拆成两段（`SwarmSystem::Render` = 两段连着调，其他调用方不变）。面板「Toon Outline」（开关、线宽、阈值、淡出、强度、颜色、`Outline Debug` 显示深度条纹）。`VFXL_NO_OUTLINE=1` 关，`VFXL_OUTLINE_DEBUG=1` 深度条纹（排查用）。没测性能（一个全屏 pass、每像素 9 次深度读取）。

  - **只读深度视图**：`Graphics` 多了 `GetReadOnlyDSV()`（`D3D11_DSV_READ_ONLY_DEPTH | READ_ONLY_STENCIL`），绑着它时可以同时把 `GetDepthSRV()` 当 SRV 读。共用的小工具 `Graphics/SceneDepthRead.h`：`Set(depthSRV, roDSV)`（场景每帧给）→ `Begin(ctx, slot)` 记下当前 RTV / DSV、换成只读 DSV、PS 的 slot 绑深度 → `End` 恢复。只在 MSAA（`GetSampleCount() > 1`，着色器用 `Texture2DMS`）时给。深度 → 目からの距離 = B / (d − A)，A = `_33 × _34`、B = `_43`（和描边、SSAO 同一式）。
  - **软粒子**（`GPUParticleSystem::softDistance` 默认 0.4m）：公告板粒子的第 2 遍（不写深度的那遍）用只读 DSV + t8 读场景深度，`GPUParticlePS::SoftFade` = (场景深度 − 自己的深度) / 宽度。普通粒子乘进颜色和 alpha；**卡通粒子不变淡而是把切线往上推**（`ToonBillboard` 的 `softK`）= 插进地面的地方形状被削掉，保持硬边。第 1 遍（不透明卡通烟、写深度）不做。0.6m 时烟在半米高的草里整体偏淡，降到 0.4m。
  - **公告板粒子吃雾**（`billboardFog` 默认开）：PS 的 b0（`ParticleSheetCB`，16 → 80B）多了雾色 / 雾距 / 深度式 / 镜头位置，雾参数取 `SetLight` 传进来的 `LightBuffer`。半透明 = 往雾色靠，加法 = 远处少加（不会变成雾色的光团）。VS 输出末尾加了 `worldPos`（TEXCOORD9，歪み的 PS 读的是前面那段，不受影响）。草原的雾 40m 才开始，几乎看不出；砂漠（10〜85m）、遗迹、砂暴里才有差别。
  - **护盾交界高光**：`VFXMeshParams` 112 → 144B，加 `intersect`（rgb = HDR 色、w = 宽 m）和 `depthAB`（Render 填）；`VFXMeshRenderer` 只要有一个 item 的 `intersect.w > 0` 就整批走只读 DSV + t3 深度（`SetSceneDepth`，场景每帧给）。`VFXMeshPS::IntersectBand` = |场景深度 − 自己的深度| / 宽，芯（0.35）+ 外圈两段硬边。**`VFXMeshPS` 的编译目标改成 5.0**（以前是 4.0_level_9_3，读不了 MSAA 纹理和 SV_POSITION）。`ShieldBubble::intersectWidth` 0.18m、`intersectColor` (1.2, 2.2, 2.8)，受击时往红色靠；面板「Bubble look」可调。
