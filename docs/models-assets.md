# 模型与素材：骨骼动画・玩家模型・素材许可

> 2026-11-13 从 CLAUDE.md 原样搬出（文字未改）。之后这一块的新记录直接追加到这里。

- **别的文件的骨骼动画**：`SkinnedModel::AddAnimationsFromFile` 按骨骼名把另一个 FBX 的片段加到已读的骨骼模型上（旋转按两边 bind 的差在父空间换算 R = R_bind * inv(A_bind) * A，平移按 hips bind 长度比缩放，自己没有的骨骼的通道丢掉；重名的片段改叫「文件名|名字」，`FindClip` 仍先找到原来的）。`Res::Mdl::kExtraAnims`（ResourcePaths.h）列「模型 → 动画文件」，`ResourceManager::ImportModelAuto` 读完骨骼模型后按路径加（预读线程里也一样）。（11-13 起 KayKit Mage 和下面这个动画包的文件都删了，`kExtraAnims` 只剩 Shadowkin 那一行）KayKit Mage（Adventurers 1.0，以前的玩家模型）加了 KayKit Character Animations 1.1（CC0）的 `Rig_Medium_MovementAdvanced.fbx`（Crouching / Sneaking / Crawling / Dodge_* 等 13 个，`Assets/Model/KayKit_CharacterAnimations/`）：骨骼名和 Mage 一致，平移比 1。该包没有滑铲动画。
  - **骨骼名不同的重定向（2026-10-04）**：`AddAnimationsFromFile(path, map, count)` 传骨骼名对应表（`Graphics/Model/BoneMaps.h`，`BoneMapEntry { target, source }`；第 1 行 = 腰（平移也重定向），左右上臂 / 头 / 腰用来对齐两个模型的朝向；**表的顺序有意义**：每根骨的「方向子骨」= 它的子孙里在表中最先出现的那个，所以手的那段把中指放在最前）时走 `RetargetAnimations`：按 30fps 采样源动画的世界旋转，取相对源基准姿势的差分，乘朝向对齐后加到自己的基准世界旋转上，再除以父骨的旋转转回父空间烘焙；腰的平移按「腰→左脚」长度比缩放。自己的**基准 = 蒙皮时的姿势**（`Invert(offset) * SubMesh::nodeGlobal`，不是节点的默认姿势），两边基准姿势的差（T / A pose、指、脚）由每根骨「骨 → 方向子骨」的最小旋转 `corr` 对齐（日志 `rest pose fixed up to N deg`）。烘出来的片段给**全部骨骼**加通道：没映射的骨（斗篷、扭转骨）用蒙皮时的父空间姿势。`ExtraAnimSet` 多了 `map / mapCount`。
  - **bind-check 分两种（2026-10-04）**：`LoadFromScene` 的 bind 检查只看有权重的骨，除了 worstDiff 还算 `spread`（这些骨之间「offset × 节点 bind」的差）。spread 小 = 所有骨偏同一个量 = mesh 节点自身带变换（KayKit Mage 的头、游侠的 2）→ 照旧按节点重建 offset（`[offset-rebuild]`）；spread 大 = 节点默认姿势和蒙皮姿势不同（Shadowkin：蒙皮是 T-pose，节点是悬浮的 ActionPose）→ 保留 FBX 的 offset（`[offset-keep]`）。以前一律重建，T-pose 的顶点挂到 A-pose 的骨上，前臂到指尖的力臂全错，爪子被甩成长线。
- **玩家模型（2026-09-28；10-04 起默认换成 Shadowkin，见下面的子项，游侠的动画仍是所有动作的来源）**：Quaternius 的游侠（白胡子老头）`Assets/Model/Quaternius_Ranger/Ranger.fbx`，全部 CC0，由 `Tools/BuildPlayerModel.py`（Blender 后台）从 4 个免费包拼成：Universal Base Characters 的头颈 + 眼 + 眉 + 胡子（胡子、眉调成白色）、Modular Character Outfits - Fantasy 的 Male_Ranger 服装、Universal Animation Library 1 + 2 里挑出的 24 段动画（同一套 65 骨 UE 式骨骼，不用重定向）。贴图缩到 1024 嵌进 FBX（约 22MB）。素材包路径很深，要解压到短路径（`%TEMP%\qp\ubc` 等），否则 Windows 260 字符限制会让 Blender 读不到服装贴图。正面是 +Z（`PlayerFactory` 的 `modelYawOffsetDeg` = 0，KayKit 是 180）。片段名在 `PlayerAnimSystem::ClipNames`（Idle_Loop / Jog_Fwd_Loop / Jump_Loop / Spell_Simple_Shoot / Hit_Chest / Death01 / Slide_Loop，上半身遮罩根 `spine_02`），FBX 里叫 `Armature|名字`，`FindClip` 按后缀匹配。加载时 `[bind-check]` 报 worstDiff=2 并重建 offset，这是正常的（offset 重建后配合 `m_GlobalInverse` 才对）。导出成 GLB 的话骨骼会被这个重建拉坏，所以只用 FBX。换回 KayKit Mage 的方法写在 `PlayerFactory.h` 的注释里。
  - **玩家 = Shadowkin（2026-10-04，用户：「用我那套 PBR 的模型试试，从虚幻的发布里下来的」，看过后选「换成默认 + 贴图压到 2K」）**：`Assets/Model/Shadowkin_SF/Shadowkin_Rigged.fbx`（Reallusion CC 骨骼 `CC_Base_*`，154 节点、单网格 8292 顶点、cm 单位，PBR 贴图在 `Tex/`，`MaterialLoader::FindTexturePath` 加了 `Tex/` 候选；贴图 3〜4K 用 ffmpeg 原地缩到 2048（94 → 25MB，原图在 git 的 171982a））。游侠的 24 段 UAL 动画用 `kBoneMapCCFromUE`（52 根骨）重定向过去（`Res::Mdl::kExtraAnims`）。`PlayerFactory::Config` 默认 `skinnedModel` = `Res::Mdl::Shadowkin`、`modelScale` 0.01、`modelYawOffsetDeg` 180（正面和游侠相反）；`kPreload` 预读它（游侠的动画文件在它里面读）。`VFXL_PLAYER=ranger` 战斗里换回游侠。`PlayerAnimSystem::ClipNames::upperRootAlt` = `CC_Base_Spine01`（上半身遮罩找不到 `spine_02` 时用）。`loco` 自测：站立 / 前后左右跑 / 斜跑 / 慢走 / 施法都正常，脚贴地，朝向对。已知：脚是模型自带的灰白色。
  - **斗篷物理（同日，用户选「Verlet 骨链」）**：Shadowkin 的斗篷是一条 8 节骨链 `Cloak1`〜`Cloak8`（+`Cloak8_end`），`Cloak1` 是独立的根骨（没挂在脊椎上，原来身体前倾时斗篷不跟）。`Component/ClothChainComponent`（配置 + 状态）+ `ECS/System/ClothChainSystem`（场景在 `SkinnedAnimSystem::Update` 之后调）：每帧用不带覆盖的姿势（`SkinnedAnimSystem::BuildPose(a, G, false)`）算出「斗篷挂在上背（`CC_Base_Spine02`）的目标形状」，在世界空间按 1/120 秒细分做 Verlet：重力 + 空气阻力（和风的相对速度：跑 5 m/s 约后扬 30〜40°）+ 风（阵风）→ 往目标形状轻拉（根强尖弱）→ 相邻距离 / 隔一个的距离（防折）/ 身体胶囊（躯干、大腿、小腿，**忽略身体左右方向测距**：链是布的中线，横向偏开的腿也能挡到布）/ 地面（`groundHeight` = 场景的高度场）约束迭代 4 次；结果转回模型空间，每根骨 = 目标形状的旋转 × 「目标方向 → 模拟方向」的最小旋转，写进 `SkinnedAnimComponent::boneOverrides`（`BuildPose` 混完层后覆盖这些骨的 global）。`SkinnedAnimSystem::WorldMatrix`（从 `RenderSystem` 挪过来，两边共用）。瞬移 > 2m 时重置。`PlayerFactory` 看到模型有 `Cloak1` 就挂 `ClothChainSystem::CCCape()`。Player 面板「Cape (cloth chain)」可调重力 / 阻力 / 阻尼 / 形状刚度 / 抗弯 / 风 / 迭代 / 布厚 / 各碰撞体半径、Reset。`SkinnedModel::GetSkinBindGlobal`（蒙皮时的骨 global）。自测 `cape`（见 docs/autotests.md）实测：站立末端在根后 0.1〜0.2m（随风摆），跑步后扬 0.6〜0.97m，急停 0.1 秒落回，跳起往下拖，滑铲压在身下。已知：单链，侧面看是一整块板，不会左右折叠。

  - **移动动画（2026-09-29，玩家反馈「滑步感」「没有后退 / 横移」）**：`PlayerAnimSystem` 在 Run 状态里按水平速度选 Walk_Loop / Jog_Fwd_Loop / Sprint_Loop（切换点 2.3 / 6.7 m/s，迟滞 ±0.2），播放速率 = 实速 / 片段原速（UAL `*_RM.glb` 的 root 位移量出来的：0.975 / 5.36 / 8.25 m/s，限 0.5〜2.0 倍），歩様之间切换时继承步伐相位。**朝向**：身体不再固定朝镜头前（用户 9-29 决定；免费 UAL 没有后退 / 横移片段，程序化扭腰 + 倒放的方案试过后放弃）。`PlayerControlSystem` 按镜头前方算出移动方向 `PlayerStateComponent::moveAngleCam`（+90 = 镜头右）和 `moveDir`（Forward / Right / Back / Left，各 ±45 度），身体以 `PlayerStatsComponent::faceTurnRate`（720 度/秒）转向移动方向，后退就转身朝镜头跑；停下时保持最后的朝向；滑铲中仍立即朝速度方向。施法瞄准本来就是自动锁敌，和朝向无关。参数在战斗场景 Player 面板「Locomotion」。
- **FBX 单位**：`Model::GetFileUnitScale()` 记录 FBX 的 UnitScaleFactor，但不乘进顶点（现有模型各自手调倍率）。KayKit Forest、Kenney、Quaternius、dglopez 的 FBX 都是厘米单位（0.01）。
- **无贴图材质的颜色（2026-09-29）**：`Material::m_Color` 在渲染里没被用过，所以「只靠材质颜色上色」的 FBX 以前全是白的。`Model::LoadFromScene` 的 `ProcessNode` 现在对**没拿到颜色贴图**的材质（包括 MaterialLoader 的同名贴图兜底也没找到的）把 `BASE_COLOR` / `COLOR_DIFFUSE` 烘进顶点色（PS 本来就是 贴图 × 顶点色）；有贴图的材质不动（Blender FBX 常写 0.8 灰，乘上会变暗）。骨骼模型（SkinnedModel）没改。已知：Modular Ruins 的 Tree_1〜3 / DeadTree_1〜3 用「白色树叶 / 树皮贴图 × 材质色」，仍然是白的。
